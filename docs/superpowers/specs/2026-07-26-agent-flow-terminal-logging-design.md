# AgentFlow 终端流程日志设计

## 目标

让默认终端输出直接展示一次 Agent 请求经过的主要环节，同时隐藏性能计时、协议载荷和底层状态机明细。需要深入排查时，可通过显式环境变量恢复现有调试日志。

## 默认输出

每轮 Work 请求使用统一的 `[AgentFlow]` 前缀，按实际执行顺序记录：

1. 开始请求：执行模式、模型和可用工具数量。
2. 准备上下文：CITA 是否完成、可信引用数量。
3. 选择动作：响应、向用户提问、调用哪个能力，或 Action Gate 失败。
4. 生成工具参数：只显示工具名和参数字段名。
5. 执行工具：开始、成功或失败。
6. 生成最终回复。
7. 本轮完成。

正常工具调用示例：

```text
[AgentFlow] ── 新请求 ─────────────────────────
[AgentFlow] 1. 准备上下文：Work 模式，34 个工具可用
[AgentFlow] 2. 理解用户请求：完成，可信引用 0 个
[AgentFlow] 3. 选择动作：调用 weather
[AgentFlow]    目标：查询北京当前天气
[AgentFlow] 4. 生成工具参数：完成（city）
[AgentFlow] 5. 执行工具：weather
[AgentFlow] 6. 工具结果：成功
[AgentFlow] 7. 生成最终回复
[AgentFlow] ── 本轮完成 ────────────────────────
```

Action Gate 失败示例：

```text
[AgentFlow] 3. 动作校验失败：TARGET_REF_INVALID
[AgentFlow]    工具未执行；转入失败回复
```

## 日志分层

默认显示：

- `[AgentFlow]` 主流程日志。
- 启动注册信息。
- 真实警告和未处理异常。

默认隐藏：

- `[Perf]`
- `[CITA/Trace]`
- `[AgentGraph/Trace]`
- `[StructuredOutput]`

设置 `CYRENE_DEBUG_LOGS=1` 后，恢复上述旧调试日志。该开关只影响日志可见性，不改变 Agent 行为。

## 结构

新增一个无业务依赖的日志模块，提供：

- 主流程输出：始终启用。
- 调试输出：仅在 `CYRENE_DEBUG_LOGS=1` 时启用。
- 参数字段摘要：只提取键名，不打印值。
- 单轮步骤编号：由调用方传入稳定的流程阶段，避免并发请求共享可变计数器。

现有性能计时仍会执行并收集数据，但默认不打印，避免为了日志改动影响运行时逻辑。CITA、Action Gate 和 LangGraph 的旧追踪日志改走调试输出。

## 数据与隐私

默认日志不得输出：

- 完整用户消息。
- 原始模型响应或结构化 JSON。
- 工具参数值。
- API Key、邮件正文、Shell 命令和文件内容。

允许输出：

- 模型 ID。
- 能力或工具 ID。
- 参数字段名。
- 引用数量。
- 成功、失败、终态、是否执行等状态。
- 本地错误码。
- Action Gate 的简短 objective；输出前压缩空白并限制长度。

## 错误处理

- Action Gate 失败必须明确打印错误码和 `工具未执行`。
- Native Function Calling 失败必须区分“参数生成失败”和“Tool Runtime 执行失败”。
- 工具运行失败打印工具 ID 和错误码，不打印原始异常中可能包含的敏感参数。
- 日志模块自身不得抛出异常或影响 Agent 路由。

## 测试

新增聚焦测试：

1. 默认状态下调试日志不输出，AgentFlow 日志输出。
2. `CYRENE_DEBUG_LOGS=1` 时旧调试日志恢复。
3. 参数摘要只包含字段名，不包含值。
4. 正常工具调用依次出现动作选择、参数生成、工具执行和成功结果。
5. `TARGET_REF_INVALID` 显示工具未执行并转入失败回复。

实现采用测试先行；先验证新测试因缺少日志能力而失败，再做最小实现并运行相关回归测试。
