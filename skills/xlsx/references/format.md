# 財務格式化與輸出標準 — 完整 Agent 指南

> 本文檔是 agent 對 xlsx 文件應用專業財務格式時的完整參考手冊。所有操作針對 `xl/styles.xml` 的直接 XML 手術，不使用 openpyxl。每個操作步驟都提供即用 XML 片段。

---

## 1. 何時使用此路徑

本文檔（FORMAT 路徑）適用於以下兩種場景：

**場景 A — 已有文件的專門格式化**
用戶提供已有 xlsx 文件，要求應用或統一財務建模格式標準。起點是解包文件、審計現有 `styles.xml`，然後追加缺失樣式並批量更新單元格 `s` 屬性。不修改單元格值或公式。

**場景 B — CREATE/EDIT 後應用格式標準**
完成數據錄入或公式編寫後，格式化作為最後步驟應用。此時 `styles.xml` 可能來自 minimal_xlsx 模板（預定義 13 個樣式槽）或來自用戶文件。無論哪種，遵循"僅追加，絕不修改已有 xf 條目"原則。

**不適用**：僅讀取或分析文件內容（用 READ 路徑）；修改公式或數據（用 EDIT 路徑）。

## 2. 財務格式語義系統

### 2.1 字體顏色 = 單元格角色（顏色 = 角色）

財務建模的首要約定：**字體顏色編碼單元格角色，而非裝飾**。審閱者可掃一眼顏色確定哪些單元格是可調參數、哪些是模型計算結果。這是全行業約定（投行、四大、企業財務團隊遵循）。

| 角色 | 字體顏色 | AARRGGBB | 用例 |
|------|-----------|----------|----------|
| 硬編碼輸入/假設 | 藍 | `000000FF` | 增長率、折現率、稅率及其他用戶可調參數 |
| 公式/計算結果 | 黑 | `00000000` | 所有含 `<f>` 元素的單元格 |
| 同工作簿跨表引用 | 綠 | `00008000` | 公式以 `SheetName!` 開頭的單元格 |
| 外部文件鏈接 | 紅 | `00FF0000` | 公式含 `[FileName.xlsx]` 的單元格（標記為脆弱鏈接） |
| 標籤/文本 | 黑（默認） | 主題色 | 行標籤、類別標題 |
| 需審閱的關鍵假設 | 藍字體 + 黃填充 | 字體 `000000FF` / 填充 `00FFFF00` | 臨時值、待確認參數 |

**決策樹**：
```
單元格是否含 <f> 元素？
  +-- 是 -> 公式是否以 [FileName] 開頭？
  |           +-- 是 -> 紅（外部鏈接）
  |           +-- 否  -> 公式是否含 SheetName!？
  |                       +-- 是 -> 綠（跨表引用）
  |                       +-- 否  -> 黑（同表公式）
  +-- 否  -> 值是否為用戶可調參數？
              +-- 是 -> 藍（輸入/假設）
              +-- 否  -> 黑默認（標籤）
```

**嚴禁**：藍字體 + `<f>` 元素共存（顏色角色矛盾 — 必須糾正）。

### 2.2 數字格式矩陣

| 數據類型 | formatCode | numFmtId | 顯示示例 | 適用場景 |
|-----------|-----------|----------|-----------------|---------------------|
| 標準貨幣（整元） | `$#,##0;($#,##0);"-"` | 164 | $1,234 / ($1,234) / - | 損益表、資產負債表金額行 |
| 標準貨幣（帶分） | `$#,##0.00;($#,##0.00);"-"` | 169 | $1,234.56 / ($1,234.56) / - | 單價、明細成本 |
| 千（K） | `#,##0,"K"` | 171 | 1,234K | 管理報告簡化顯示 |
| 百萬（M） | `#,##0,,"M"` | 172 | 1M | 宏觀彙總行 |
| 百分比（1 位小數） | `0.0%` | 165 | 12.5% | 增長率、毛利率 |
| 百分比（2 位小數） | `0.00%` | 170 | 12.50% | IRR、精確利率 |
| 倍數/估值乘數 | `0.0x` | 166 | 8.5x | EV/EBITDA、P/E |
| 整數（千位分隔） | `#,##0` | 167 | 12,345 | 員工數、單位數量 |
| 年份 | `0` | 1（內置，無需聲明） | 2024 | 列標題年份，防止 2,024 |
| 日期 | `m/d/yyyy` | 14（內置，無需聲明） | 3/21/2026 | 時間線 |
| 常規文本 | General | 0（內置，無需聲明） | — | 標籤行、無格式要求的單元格 |

numFmtId 169–172 是自定義格式，需在 minimal_xlsx 模板預定義的 4 個格式（164–167）之外追加。追加時按規則分配 ID（見第 3.4 節）。

**內置格式 ID 無需在 `<numFmts>` 中聲明**（ID 0–163 是 Excel/LibreOffice 內置的；在 `<xf>` 中直接引用 numFmtId 即可）：

| numFmtId | formatCode | 說明 |
|----------|-----------|-------------|
| 0 | General | 常規格式 |
| 1 | `0` | 整數，無千位分隔（年份用此 ID） |
| 3 | `#,##0` | 千位分隔整數（無小數） |
| 9 | `0%` | 百分比整數 |
| 10 | `0.00%` | 兩位小數百分比 |
| 14 | `m/d/yyyy` | 短日期 |

### 2.3 負數顯示標準

財務報告對負數有兩種主流約定 — 選一種並在整個工作簿中**保持一致**：

**括號樣式（投行標準，外部交付物推薦）**

```
正：$1,234    負：($1,234)    零：-
formatCode: $#,##0;($#,##0);"-"
```

**紅色減號樣式（適合內部運營分析報告）**

```
正：$1,234    負：-$1,234（紅）
formatCode: $#,##0;[Red]-$#,##0;"-"
```

規則：一旦確定樣式，整個工作簿保持一致。不要在同一工作簿內混用兩種負數顯示樣式。

### 2.4 零值顯示標準

財務模型中，"0"和"無數據"語義不同，應視覺區分：

| 場景 | 推薦顯示 | formatCode 第三段 |
|----------|-------------------|--------------------------|
| 稀疏矩陣（多數行有零值期） | 破折號 `-` | `"-"` |
| 數量計數（零本身有意義） | `0` | `0` 或省略 |
| 佔位行（顯式空） | 留空 | 不寫入單元格 |

四段格式語法：`正數格式;負數格式;零值格式;文本格式`

零顯示為破折號：`$#,##0;($#,##0);"-"`
零保留為 0：`#,##0;(#,##0);0`

## 3. styles.xml 手術操作

### 3.1 審計現有樣式：理解 cellXfs 間接引用鏈

單元格的 `s` 屬性指向 `cellXfs` 中的位置索引（0 起始），`cellXfs` 中每個 `<xf>` 條目通過 `fontId`、`fillId`、`borderId`、`numFmtId` 引用各自定義庫。

引用鏈示意圖：

```
單元格 <c s="6">
    | 按 0 起始索引查 cellXfs
cellXfs[6] -> numFmtId="164" fontId="2" fillId="0" borderId="0"
    |            |               |          |
numFmts         fonts[2]      fills[0]   borders[0]
id=164          color=00000000  (無填充)  (無邊框)
$#,##0...       黑
```

審計步驟：

**第 1 步**：讀 `<numFmts>`，記錄所有聲明的自定義格式及其 ID：
```xml
<numFmts count="4">
  <numFmt numFmtId="164" formatCode="$#,##0;($#,##0);&quot;-&quot;"/>
  <numFmt numFmtId="165" formatCode="0.0%"/>
  <numFmt numFmtId="166" formatCode="0.0x"/>
  <numFmt numFmtId="167" formatCode="#,##0"/>
</numFmts>
```
記錄：當前最大自定義 numFmtId = 167，下一個可用 ID = 168。

**第 2 步**：讀 `<fonts>`，按 0 起始索引列出每個 `<font>` 的顏色和樣式：
```
fontId=0 -> 無顯式顏色（主題默認黑）
fontId=1 -> color rgb="000000FF"（藍，輸入角色）
fontId=2 -> color rgb="00000000"（黑，公式角色）
fontId=3 -> color rgb="00008000"（綠，跨表引用角色）
fontId=4 -> <b/> + color rgb="00000000"（粗體黑，表頭）
```

**第 3 步**：讀 `<fills>`，確認 fills[0] 和 fills[1] 是規範強制的保留條目（絕不刪除）：
```
fillId=0 -> patternType="none"（規範強制）
fillId=1 -> patternType="gray125"（規範強制）
fillId=2 -> 黃色高亮（若存在）
```

**第 4 步**：讀 `<cellXfs>`，按 0 起始索引列出每個 `<xf>` 條目的組合：
```
索引 0 -> numFmtId=0,   fontId=0, fillId=0 -> 默認樣式
索引 1 -> numFmtId=0,   fontId=1, fillId=0 -> 藍字體常規（輸入）
索引 5 -> numFmtId=164, fontId=1, fillId=0 -> 藍字體貨幣（貨幣輸入）
索引 6 -> numFmtId=164, fontId=2, fillId=0 -> 黑字體貨幣（貨幣公式）
...
```

**第 5 步**：驗證所有 count 屬性與實際元素數匹配（count 不匹配會導致 Excel 拒絕打開文件）。

### 3.2 安全追加新樣式（黃金規則：僅追加，絕不修改已有 xf）

**絕不修改已有 `<xf>` 條目**。修改會影響所有已引用該索引的單元格，破壞現有格式。只在末尾追加新條目。

追加新樣式的完整原子操作序列（5 步都必須執行）：

**第 1 步**：確定是否需要新 `<numFmt>`

內置格式（ID 0–163）跳過此步。自定義格式追加到 `<numFmts>` 末尾：
```xml
<numFmts count="5">  <!-- count +1 -->
  <!-- 保持現有條目不變 -->
  <numFmt numFmtId="164" formatCode="$#,##0;($#,##0);&quot;-&quot;"/>
  <numFmt numFmtId="165" formatCode="0.0%"/>
  <numFmt numFmtId="166" formatCode="0.0x"/>
  <numFmt numFmtId="167" formatCode="#,##0"/>
  <!-- 新追加 -->
  <numFmt numFmtId="168" formatCode="$#,##0.00;($#,##0.00);&quot;-&quot;"/>
</numFmts>
```

**第 2 步**：確定是否需要新 `<font>`

檢查現有字體是否已含匹配的顏色+樣式組合。若無，追加到 `<fonts>` 末尾：
```xml
<fonts count="6">  <!-- count +1 -->
  <!-- 保持現有條目不變 -->
  ...
  <!-- 新追加：紅字體（外部鏈接角色），新 fontId = 5 -->
  <font>
    <sz val="11"/>
    <name val="Calibri"/>
    <color rgb="00FF0000"/>
  </font>
</fonts>
```
新 fontId = 追加前的 count 值（原 count=5 時，新 fontId=5）。

**第 3 步**：確定是否需要新 `<fill>`

若需新背景色，追加到 `<fills>` 末尾（注意：fills[0] 和 fills[1] 絕不可修改）：
```xml
<fills count="4">  <!-- count +1 -->
  <fill><patternFill patternType="none"/></fill>       <!-- 0: 規範強制 -->
  <fill><patternFill patternType="gray125"/></fill>    <!-- 1: 規範強制 -->
  <fill>                                               <!-- 2: 黃色高亮 -->
    <patternFill patternType="solid">
      <fgColor rgb="00FFFF00"/>
      <bgColor indexed="64"/>
    </patternFill>
  </fill>
  <!-- 新追加：淺灰填充（預測期區分），新 fillId = 3 -->
  <fill>
    <patternFill patternType="solid">
      <fgColor rgb="00D3D3D3"/>
      <bgColor indexed="64"/>
    </patternFill>
  </fill>
</fills>
```

**第 4 步**：在 `<cellXfs>` 末尾追加新 `<xf>` 組合
```xml
<cellXfs count="14">  <!-- count +1 -->
  <!-- 保持現有條目 0-12 不變 -->
  ...
  <!-- 新追加索引=13：帶分貨幣公式（黑字體 + numFmtId=168） -->
  <xf numFmtId="168" fontId="2" fillId="0" borderId="0" xfId="0"
      applyFont="1" applyNumberFormat="1"/>
</cellXfs>
```
新樣式索引 = 追加前的 count 值（原 count=13 時，新索引=13）。

**第 5 步**：記錄新樣式索引；隨後將工作表 XML 中對應單元格的 `s` 屬性設為此值。

### 3.3 AARRGGBB 顏色格式說明

OOXML 的 `rgb` 屬性用 **8 位十六進制 AARRGGBB** 格式（非 HTML 的 6 位 RRGGBB）：

```
AA  RR  GG  BB
|   |   |   |
Alpha 紅 綠 藍
```

- Alpha 通道：`00` = 完全不透明（正常用值）；`FF` = 完全透明（不可見，絕不用）
- 財務顏色標準始終用 `00` 作 Alpha 前綴

| 顏色 | AARRGGBB | 對應角色 |
|-------|----------|-------------------|
| 藍（輸入） | `000000FF` | 硬編碼假設 |
| 黑（公式） | `00000000` | 計算結果 |
| 綠（跨表引用） | `00008000` | 同工作簿跨表 |
| 紅（外部鏈接） | `00FF0000` | 引用其他文件 |
| 黃（需審閱填充） | `00FFFF00` | 關鍵假設高亮 |
| 淺灰（預測期填充） | `00D3D3D3` | 區分歷史與預測期 |
| 白 | `00FFFFFF` | 純白填充 |

**常見錯誤**：誤將 HTML 格式 `#0000FF` 寫成 `FF0000FF`（Alpha=FF 使顏色完全透明不可見）。正確格式：`000000FF`。

### 3.4 numFmtId 分配規則

```
ID 0-163    -> Excel/LibreOffice 內置格式，無需在 <numFmts> 聲明，在 <xf> 中直接引用
ID 164+     -> 自定義格式，必須在 <numFmts> 中顯式聲明為 <numFmt> 元素
```

分配新 ID 規則：
1. 讀取當前 `<numFmts>` 中所有 `numFmtId` 屬性值
2. 取最大值 + 1 作為下一個自定義格式 ID
3. 不復用已有 ID；不跳號

minimal_xlsx 模板預定義 ID：164、165、166、167。下一個可用 ID 為 168。

## 4. 預定義樣式索引完整參考表（13 槽）

以下是 minimal_xlsx 模板 `styles.xml` 中預定義的 13 個樣式槽（cellXfs 索引 0–12），可在工作表 XML 的單元格 `s` 屬性中直接引用：

| 索引 | 語義角色 | 字體顏色 | 填充 | numFmtId | 格式顯示 | 典型用途 |
|-------|--------------|------------|------|----------|---------------|-------------|
| **0** | 默認樣式 | 主題黑 | 無 | 0 | General | 無需特殊格式的單元格 |
| **1** | 輸入/假設（常規） | 藍 `000000FF` | 無 | 0 | General | 文本型假設、標誌 |
| **2** | 公式/計算結果（常規） | 黑 `00000000` | 無 | 0 | General | 文本拼接公式、非數字計算 |
| **3** | 跨表引用（常規） | 綠 `00008000` | 無 | 0 | General | 從跨表拉取的值（常規格式） |
| **4** | 表頭（粗體） | 粗體黑 | 無 | 0 | General | 行/列標題 |
| **5** | 貨幣輸入 | 藍 `000000FF` | 無 | 164 | $1,234 / ($1,234) / - | 假設區的金額輸入 |
| **6** | 貨幣公式 | 黑 `00000000` | 無 | 164 | $1,234 / ($1,234) / - | 模型區的金額計算（營收、EBITDA） |
| **7** | 百分比輸入 | 藍 `000000FF` | 無 | 165 | 12.5% | 假設區的比率輸入（增長率、毛利率假設） |
| **8** | 百分比公式 | 黑 `00000000` | 無 | 165 | 12.5% | 模型區的比率計算（實際毛利率） |
| **9** | 整數（逗號）輸入 | 藍 `000000FF` | 無 | 167 | 12,345 | 假設區的數量輸入（員工數） |
| **10** | 整數（逗號）公式 | 黑 `00000000` | 無 | 167 | 12,345 | 模型區的數量計算 |
| **11** | 年份輸入 | 藍 `000000FF` | 無 | 1 | 2024 | 列標題年份（無千位分隔） |
| **12** | 關鍵假設高亮 | 藍 `000000FF` | 黃 `00FFFF00` | 0 | General | 待審閱或確認的關鍵參數 |

**選擇指南**：
- 確定"輸入"vs"公式" -> 選奇數（輸入/藍）或偶數（公式/黑）配對槽
- 確定數據類型 -> 選對應貨幣（5/6）/百分比（7/8）/整數（9/10）/年份（11）槽
- 需數字格式的跨表引用 -> 追加新綠+數字格式組合（見第 5.4 節）
- 待審閱參數 -> 索引 12

## 5. 假設分離原則：XML 層實現

### 5.1 結構設計

假設分離原則：**輸入假設集中在專門區域（工作表或塊）；模型計算區只含公式，無硬編碼值**。

推薦結構：
```
工作簿工作表佈局
  工作表 1 "Assumptions"  -> 所有藍字體單元格（樣式 1/5/7/9/11/12）
  工作表 2 "Model"        -> 所有黑或綠字體單元格（樣式 2/3/4/6/8/10）
```

簡單模型的同表分區法：
```
第 1-5 行：  [假設塊 - 藍字體]
第 6 行：    [空行分隔]
第 7+ 行：   [模型塊 - 黑/綠字體公式引用假設區]
```

### 5.2 假設區 XML 示例

```xml
<!-- Assumptions 工作表（sheet1.xml）示例 -->

<!-- 第 1 行：塊標題 -->
<row r="1">
  <c r="A1" s="4" t="inlineStr"><is><t>模型假設</t></is></c>
</row>

<!-- 第 2 行：增長率假設 - 藍字體百分比輸入，s="7" -->
<row r="2">
  <c r="A2" t="inlineStr"><is><t>營收增長率</t></is></c>
  <c r="B2" s="7"><v>0.08</v></c>
</row>

<!-- 第 3 行：毛利率假設 - 藍字體百分比輸入，s="7" -->
<row r="3">
  <c r="A3" t="inlineStr"><is><t>毛利率</t></is></c>
  <c r="B3" s="7"><v>0.65</v></c>
</row>

<!-- 第 4 行：基礎營收 - 藍字體貨幣輸入，s="5" -->
<row r="4">
  <c r="A4" t="inlineStr"><is><t>基礎營收（第 0 年）</t></is></c>
  <c r="B4" s="5"><v>1000000</v></c>
</row>

<!-- 第 5 行：關鍵假設（待審閱）- 藍字體黃填充，s="12" -->
<row r="5">
  <c r="A5" t="inlineStr"><is><t>終值增長率</t></is></c>
  <c r="B5" s="12"><v>0.03</v></c>
</row>
```

### 5.3 模型區 XML 示例（引用假設區）

```xml
<!-- Model 工作表（sheet2.xml）示例 -->

<!-- 第 1 行：列標題（年份）- 粗體表頭，s="4"；年份單元格，s="11" -->
<row r="1">
  <c r="A1" s="4" t="inlineStr"><is><t>指標</t></is></c>
  <c r="B1" s="11"><v>2024</v></c>
  <c r="C1" s="11"><v>2025</v></c>
  <c r="D1" s="11"><v>2026</v></c>
</row>

<!-- 第 2 行：營收行 -->
<row r="2">
  <c r="A2" t="inlineStr"><is><t>營收</t></is></c>
  <!-- B2：基年營收，從 Assumptions 跨表引用，綠，s="3"（常規格式） -->
  <!-- 若需貨幣格式，追加新樣式 s="13"（見第 5.4 節） -->
  <c r="B2" s="3"><f>Assumptions!B4</f><v></v></c>
  <!-- C2、D2：次年營收 = 前年 * (1 + 增長率)，黑字體貨幣公式，s="6" -->
  <c r="C2" s="6"><f>B2*(1+Assumptions!B2)</f><v></v></c>
  <c r="D2" s="6"><f>C2*(1+Assumptions!B2)</f><v></v></c>
</row>

<!-- 第 3 行：毛利行 - 黑字體貨幣公式，s="6" -->
<row r="3">
  <c r="A3" t="inlineStr"><is><t>毛利</t></is></c>
  <c r="B3" s="6"><f>B2*Assumptions!B3</f><v></v></c>
  <c r="C3" s="6"><f>C2*Assumptions!B3</f><v></v></c>
  <c r="D3" s="6"><f>D2*Assumptions!B3</f><v></v></c>
</row>

<!-- 第 4 行：毛利率行 - 黑字體百分比公式，s="8" -->
<row r="4">
  <c r="A4" t="inlineStr"><is><t>毛利率 %</t></is></c>
  <c r="B4" s="8"><f>B3/B2</f><v></v></c>
  <c r="C4" s="8"><f>C3/C2</f><v></v></c>
  <c r="D4" s="8"><f>D3/D2</f><v></v></c>
</row>
```

### 5.4 追加"綠+數字格式"組合

預定義索引 3 是綠字體+常規格式。若跨表引用涉及貨幣金額，必須追加帶數字格式的綠色樣式：

```xml
<!-- 在 styles.xml 的 <cellXfs> 末尾追加（假設當前 count=13，新索引=13） -->
<!-- 索引 13：跨表引用 + 貨幣格式（綠字體 + $#,##0） -->
<xf numFmtId="164" fontId="3" fillId="0" borderId="0" xfId="0"
    applyFont="1" applyNumberFormat="1"/>
<!-- 更新 count 為 14 -->
```

追加後，跨表引用貨幣單元格用 `s="13"`。

### 6.1 工作流概覽

```
[已有 xlsx 或 CREATE/EDIT 後的文件]
        |
  第 1 步：解包（解壓到臨時目錄）
        |
  第 2 步：審計 styles.xml（審查現有樣式，構建索引映射表）
```

## 7. 格式化完整性檢查清單

交付前驗證每項：

### 顏色角色一致性
- [ ] 所有含 `<f>` 元素的數字單元格：fontId 對應黑（公式）或綠（跨表引用）
- [ ] 所有用戶可調參數的硬編碼數字值：fontId 對應藍（輸入）
- [ ] 跨表引用（公式含 `SheetName!`）：fontId 對應綠
- [ ] 外部文件引用（公式含 `[FileName.xlsx]`）：fontId 對應紅
- [ ] 無單元格同時含 `<f>` 元素並使用藍字體（顏色角色矛盾）

### 數字格式正確性
- [ ] 年份列：numFmtId="1"（`0` 格式），顯示為 2024 而非 2,024
- [ ] 貨幣行：numFmtId="164" 或變體，負數顯示為 ($1,234) 而非 -$1,234
- [ ] 百分比行：值以小數存儲（0.08 = 8%），格式 numFmtId="165"，顯示為 8.0%
- [ ] 零值：在稀疏矩陣中顯示為 `-` 而非 `0`（formatCode 第三段含 `"-"`）
- [ ] 倍數行（EV/EBITDA 等）：numFmtId="166"（`0.0x` 格式）
- [ ] 負數顯示樣式在整個工作簿一致（括號或紅色減號）

### styles.xml 結構完整性
- [ ] `<numFmts count>` = 實際 `<numFmt>` 元素數
- [ ] `<fonts count>` = 實際 `<font>` 元素數
- [ ] `<fills count>` = 實際 `<fill>` 元素數（含規範強制的 fills[0] 和 fills[1]）
- [ ] `<cellXfs count>` = 實際 `<xf>` 元素數
- [ ] fills[0] 為 `patternType="none"`，fills[1] 為 `patternType="gray125"`（規範強制）
- [ ] 所有 `<xf>` 引用的 fontId / fillId / borderId 在各自集合有效範圍內
- [ ] 所有單元格 `s` 屬性值 < `cellXfs count`（無越界引用）

### 假設分離驗證
- [ ] 假設區/表中無黑字體數字單元格（黑色數字 = 公式，不應在假設中）
- [ ] 模型區/表中無藍字體非年份數字單元格（藍色數字 = 硬編碼，應在假設中）
- [ ] 模型區的輸入參數通過公式引用假設區，而非直接複製值

### 公式與格式聯動
- [ ] 所有含 `<f>` 元素的單元格都有顯式 `s` 屬性（不得用默認 style=0，其字體顏色非顯式黑）
- [ ] SUM 彙總行：樣式用黑字體 + 對應數字格式（如貨幣彙總用 s="6"）
- [ ] 百分比公式：值以小數存儲，格式為 `0.0%`；不要在應用百分比格式前將值乘以 100

### 視覺層級
- [ ] 表頭行（年份/指標名）：style=4（粗體黑）
- [ ] 彙總行（Total/EBITDA/Net Income）：粗體 + 對應數字格式（需要時追加樣式）
- [ ] 單位說明行（如"$ 千"）：用 style=0 或 style=2（無需藍）

## 8. 禁止操作（絕不可做）

- **不修改已有 `<xf>` 條目**：會批量改變所有引用該索引的單元格樣式
- **不刪除 fills[0] 和 fills[1]**：OOXML 規範要求；刪除導致文件損壞
- **不修改單元格值或公式**：FORMAT 路徑只改樣式，不改內容
- **不用 openpyxl 格式化**：openpyxl 保存時重寫整個 styles.xml，丟失不支持的功能
- **不應用全局覆蓋樣式**：不要用單一樣式覆蓋整個工作簿；按語義角色精確分配
- **不在 Alpha 通道寫 FF**：`rgb="FF0000FF"` 使顏色完全透明；正確格式為 `rgb="000000FF"`

## 9. 常見錯誤與修復

### 錯誤 1：年份顯示為 2,024

原因：年份單元格的 `s` 屬性用了帶千位分隔的格式（如 numFmtId="3" 或 numFmtId="167"）。

```xml
<!-- 錯誤 -->
<c r="B1" s="9"><v>2024</v></c>

<!-- 修復：改為 s="11"（numFmtId="1"，格式 0） -->
<c r="B1" s="11"><v>2024</v></c>
```

### 錯誤 2：百分比顯示為 800%（值被乘以 100）

原因：8% 存為 `<v>8</v>` 而非 `<v>0.08</v>`。Excel 的 `%` 格式自動將值乘以 100 顯示。

```xml
<!-- 錯誤 -->
<c r="B2" s="7"><v>8</v></c>

<!-- 修復：值必須以小數形式存儲 -->
<c r="B2" s="7"><v>0.08</v></c>
```

### 錯誤 3：追加樣式未更新 count 導致文件損壞

原因：追加了 `<font>` 或 `<xf>` 元素但未更新 count 屬性；Excel 用舊 count 越界讀取。

修復：每追加一個元素後立即更新對應 count：
```xml
<!-- 追加第 6 個字體後，count 必須從 5 改為 6 -->
<fonts count="6">
  ...
</fonts>
```

### 錯誤 4：藍字體 + 公式（顏色角色矛盾）

原因：公式單元格誤用輸入樣式（如貨幣輸入 s="5"）。

```xml
<!-- 錯誤：公式單元格用藍色輸入樣式 -->
<c r="C5" s="5"><f>B5*1.08</f><v></v></c>

<!-- 修復：公式單元格改為對應黑色公式樣式（5->6, 7->8, 9->10） -->
<c r="C5" s="6"><f>B5*1.08</f><v></v></c>
```

### 錯誤 5：AARRGGBB 顏色缺 Alpha（僅 6 位）

```xml
<!-- 錯誤：6 位格式，行為取決於實現，通常導致顏色錯誤 -->
<color rgb="0000FF"/>

<!-- 修復：始終用 8 位 AARRGGBB，Alpha 固定 00 -->
<color rgb="000000FF"/>
```

### 錯誤 6：修改已有 xf（影響所有引用該索引的單元格）

原因：直接修改 cellXfs 中第 N 個 `<xf>` 的屬性，導致所有 `s="N"` 的單元格被批量改變。

修復：保持現有條目不變，在末尾追加新條目，只將需新樣式單元格的 `s` 屬性改為新索引：
```xml
<!-- 錯誤：修改了索引=6 的已有 xf -->
<xf numFmtId="164" fontId="2" fillId="0" borderId="0" xfId="0"
    applyFont="1" applyNumberFormat="1" applyAlignment="1">
  <alignment horizontal="right"/>  <!-- 新增屬性，影響所有已用 s="6" 的單元格 -->
</xf>

<!-- 修復：追加新索引（原 count=13 時，新索引=13），只改需右對齊單元格的 s 屬性 -->
<!-- 索引=6 保持原樣 -->
<xf numFmtId="164" fontId="2" fillId="0" borderId="0" xfId="0"
    applyFont="1" applyNumberFormat="1" applyAlignment="1">
  <alignment horizontal="right"/>
</xf>  <!-- 新索引=13 -->
```

## 10. 財務模型結構約定

### 10.1 表頭行

- 粗體字體（對應本 skill 模板的樣式索引 4）

### 10.2 行類型標準

| 行類型 | 樣式建議 | 示例 |
|----------|---------------------|---------|

### 10.3 多年模型列布局


## 11. 假設類別

在假設區（Assumptions 表或假設塊），按以下標準順序組織假設以便審閱和維護：

1. **營收假設**：增長率、定價、銷量
2. **成本假設**：毛利率、固定/可變成本比率
3. **營運資金**：DSO（應收賬款週轉天數）、DPO（應付賬款週轉天數）、庫存天數
4. **資本支出（CapEx）**：佔營收百分比或絕對金額
5. **融資假設**：利率、債務償還計劃
6. **稅務及其他**：有效稅率、折舊攤銷（D&A）

## 12. 審計追蹤最佳實踐

- 用 `s="12"`（藍字體 + 黃填充高亮）標記需審閱或待改動的單元格，使其對審閱者立即可見
- 在敏感性分析行或單獨的 Sensitivity 標籤頁，展示關鍵假設 +/-1% 變化對結果的影響
- **不隱藏含假設的行**：假設行必須對審閱者可見；不要用 `hidden="1"` 屬性
- 在假設區頂部或專門單元格註明"最後更新"日期，記錄模型最後修改時間
