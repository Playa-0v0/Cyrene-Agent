## 1. 留白與呼吸空間

### 為何有效

人眼並非連續閱讀。它以掃視（saccades）跳動，固定在小的詞簇上。留白為這些注視點提供著陸區，並給讀者的周邊視覺一個"畫框"，使每個文本塊感覺易於處理。當頁面被塞滿到邊緣時，每次瞥見返回的文本超過工作記憶能緩衝的量，引發疲勞和迴避。

關於內容密度的研究一致表明：

- **60-70% 內容覆蓋率**感覺舒適且專業。
- **80%+** 開始感覺密集、官僚。
- **90%+** 感覺壓抑 — 讀者不自覺地趕讀或跳讀。
- **低於 50%** 感覺浪費或做作（除非有意為之，如詩歌）。

更寬的頁邊距還承載文化信號。學術和奢華文檔使用慷慨的頁邊距（1.25-1.5 英寸）。內部備忘錄和草稿使用較窄的頁邊距（0.75-1.0 英寸）。頁邊距寬度在讀者讀到一個字之前就告訴了他們文檔投入了多少心思。

行距有直接的生理基礎：每次換行後，眼睛必須追蹤回到下一行開頭。若行距太近，眼睛會"滑"到錯誤的行。若太遠，眼睛失去連續感。最佳點是字號的 120-145%。

**經驗法則：拿不準時，多留空間，而非少留。**

### 好的示例

```
商業文檔四邊頁邊距：1 英寸（1440 twips）。
行距：1.15（240 twips 每行下 276 twips = 115%）。
正文段後距：8pt（160 twips）。
```

```xml
<!-- 頁邊距：四邊 1 英寸 = 1440 twips -->
<w:pgMar w:top="1440" w:right="1440" w:bottom="1440" w:left="1440"
         w:header="720" w:footer="720" w:gutter="0"/>

<!-- 正文段落：1.15 行距，段後 8pt -->
<w:pPr>
  <w:spacing w:after="160" w:line="276" w:lineRule="auto"/>
</w:pPr>
```

這產生的頁面內容約佔 65% 面積。讀者看到清晰的上下呼吸空間，段落分明又不顯得割裂。

```
  頁面佈局（好）：
  +----------------------------------+
  |           1" 頁邊距               |
  |   +------------------------+    |
  |   | 標題                   |    |
  |   |                        |    |
  |   | 正文在此，行間有        |    |
  |   | 舒適的間距。            |    |
  |   |                        |    |
  |   |                        |    |  <- 段落間可見間隙
  |   | 另一段正文緊隨其後。     |    |
  |   |                        |    |
  |   +------------------------+    |
  |           1" 頁邊距               |
  +----------------------------------+
```

### 壞的示例

```xml
<!-- 擁擠的頁邊距：0.5 英寸 = 720 twips -->
<w:pgMar w:top="720" w:right="720" w:bottom="720" w:left="720"
         w:header="360" w:footer="360" w:gutter="0"/>

<!-- 無段間距，單倍行距 -->
<w:pPr>
  <w:spacing w:after="0" w:line="240" w:lineRule="auto"/>
</w:pPr>
```

這填滿約 85% 頁面。文本從邊到邊，無視覺休息點。讀者看到一堵文字牆。

```
  頁面佈局（壞）：
  +----------------------------------+
  | 標題                              |
  | 正文緊貼頁邊距，行間和段間        |
  | 沒有任何間距。另一段從這裡        |
  | 開始，讀者分不清一個意思在哪      |
  | 結束、另一個從哪開始，因為一切    |
  | 都模糊成一個密集的文字塊。        |
  +----------------------------------+
```

### 快速測試

1. 在文檔查看器中縮放到 50%。若你看不到文本塊之間清晰的白色"通道"，間距太緊。
2. 打印測試頁。一臂距離持看。文本區應像懸浮於白色中的矩形，而非填滿整頁。
3. 檢查：正文行距值是否至少 264（1.1x 的 `w:line`）？若是 240（單倍），對超過 10pt 的任何內容都太緊。

## 2. 對比與比例

### 為何有效

大腦通過相對差異而非絕對大小處理視覺層級。11pt 正文上方的 20pt 標題產生清晰的"這很重要"信號。但若每個標題都是 20pt、每個副標題都是 19pt，大腦無法區分 — 它們合併為同一級。

關鍵洞見是**模數比例**：按一致比率增長的字號。這映射自然比例，之所以和諧，與音樂音程同理。

常見比例及其性格：

| 比率 | 名稱           | 性格                       | 示例進程（從 11pt） |
|-------|----------------|---------------------------------|---------------------------------|
| 1.200 | 小三度    | 微妙、精緻                 | 11 → 13.2 → 15.8 → 19.0       |
| 1.250 | 大三度    | 平衡、專業          | 11 → 13.75 → 17.2 → 21.5      |
| 1.333 | 純四度 | 強烈、權威           | 11 → 14.7 → 19.5 → 26.0       |
| 1.414 | 增四度  | 戲劇、演示風格    | 11 → 15.6 → 22.0 → 31.1       |

對大多數商業文檔，1.25（大三度）效果最佳：

```
正文  = 11pt  (w:sz="22")
H3    = 13pt  (w:sz="26")   -- 11 * 1.25 ≈ 13.75，取整 13
H2    = 16pt  (w:sz="32")   -- 13 * 1.25 ≈ 16.25，取整 16
H1    = 20pt  (w:sz="40")   -- 16 * 1.25 = 20
```

除字號外，**字重對比**在不消耗垂直空間的情況下創造層級。Regular（400）vs Bold（700）在任何尺寸下都可見。Semi-bold（600）vs Regular 很微妙，最好避免，除非同時變化字號或顏色。

**顏色對比**增加第三維度。深藍標題（#1F3864）配較柔和的深灰正文（#333333）無需巨大字號跳躍即可暗示"標題"。純黑（#000000）正文在白底上比必要的更刺眼 — #333333 或 #2D2D2D 降低眩光又不失可讀性。

### 好的示例

```xml
<!-- H1：20pt，粗體，深海軍藍 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="40"/>
  <w:color w:val="1F3864"/>
</w:rPr>

<!-- H2：16pt，粗體，深海軍藍 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="32"/>
  <w:color w:val="1F3864"/>
</w:rPr>

<!-- H3：13pt，粗體，深海軍藍 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="26"/>
  <w:color w:val="1F3864"/>
</w:rPr>

<!-- 正文：11pt，常規，深灰 -->
<w:rPr>
  <w:sz w:val="22"/>
  <w:color w:val="333333"/>
</w:rPr>
```

```
  視覺層級（好）：

  [████████████████████]        <- H1：20pt 粗體海軍藍（明顯主導）
                                   （慷慨間距）
  [██████████████]              <- H2：16pt 粗體海軍藍（明顯低一級）
                                   （適中間距）
  [████████████]                <- H3：13pt 粗體海軍藍（更小但仍粗體）
  [░░░░░░░░░░░░░░░░░░░░░░]    <- 正文：11pt 常規灰
  [░░░░░░░░░░░░░░░░░░░░░░]
  [░░░░░░░░░░░░░░░░░░░░░░]
```

每級與相鄰級視覺上分明。即便在周邊視覺中也能識別層級。

### 壞的示例

```xml
<!-- H1：14pt 粗體黑 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="28"/>
  <w:color w:val="000000"/>
</w:rPr>

<!-- H2：13pt 粗體黑 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="26"/>
  <w:color w:val="000000"/>
</w:rPr>

<!-- H3：12pt 粗體黑 -->
<w:rPr>
  <w:b/>
  <w:sz w:val="24"/>
  <w:color w:val="000000"/>
</w:rPr>

<!-- 正文：12pt 常規黑 -->
<w:rPr>
  <w:sz w:val="24"/>
  <w:color w:val="000000"/>
</w:rPr>
```

問題：
- H3（12pt 粗體）與正文（12pt 常規）僅字重不同 — 太微妙。
- H1（14pt）到 H2（13pt）是 1pt 步進 — 閱讀距離下不可見。
- 一切都是純黑，顏色不提供區分信號。
- 各級間比率約 1.07，過於扁平。

### 快速測試

1. **眯眼測試**：模糊視線或遠離屏幕。你能數出標題層級數嗎？若兩級合併，對比不足。
2. **比率檢查**：每個標題字號除以下一級字號。若任何比率低於 1.15，兩級會看起來太相似。
3. **顏色檢查**：掃視頁面時，標題與正文是否看起來分明？若一切同色，你僅靠字號/字重，這把層級限制在約 3 個有效級別。

## 3. 鄰近與分組

### 為何有效

格式塔鄰近原則：靠得近的項目被感知為同組。在文檔排版中，這意味著標題必須**更靠近它所引入的內容**，而非上方內容。

若標題等距於兩段之間，它看起來孤立 — 讀者眼睛不知道它屬於上方還是下方文本。修復是非對稱間距：**標題前大間距，後小間距**。

推薦比率是 2:1 或 3:1（段前 : 段後）。

同一原則適用於：
- **列表項**：項間距應小於段間距。列表中的項是一組，應視覺聚簇。
- **題注**：圖注應靠近其圖，而非漂浮在圖與下一段之間。
- **表格標題**：標題緊貼表格上方，與上方文本有更多間距分隔。

### 好的示例

```xml
<!-- H2：前 18pt，後 6pt（3:1 比率） -->
<w:pPr>
  <w:pStyle w:val="Heading2"/>
  <w:spacing w:before="360" w:after="120"/>
</w:pPr>

<!-- 正文段落：前 0pt，後 8pt -->
<w:pPr>
  <w:spacing w:before="0" w:after="160"/>
</w:pPr>

<!-- 列表項：前 0pt，後 2pt（緊密分組） -->
<w:pPr>
  <w:pStyle w:val="ListParagraph"/>
  <w:spacing w:before="0" w:after="40"/>
</w:pPr>
```

```
  鄰近（好）：

  ...上一節文本結束。
                                        <- 18pt 間隙 (w:before="360")
  ## 章節標題
                                        <- 6pt 間隙 (w:after="120")
  新節第一段
  內容在此繼續。
                                        <- 8pt 間隙 (w:after="160")
  第二段緊隨。

  標題明顯"歸屬於"下方文本。
```

```
  列表分組（好）：

  考慮這些因素：
    - 第一項                        <- 項間 2pt 間隙
    - 第二項                        <- 項作為一組聚簇
    - 第三項
                                        <- 列表後 8pt 間隙
  下一段從這裡開始。
```

### 壞的示例

```xml
<!-- H2：前 12pt，後 12pt（1:1 比率 — 孤立標題） -->
<w:pPr>
  <w:pStyle w:val="Heading2"/>
  <w:spacing w:before="240" w:after="240"/>
</w:pPr>

<!-- 列表項：與正文同間距（後 10pt） -->
<w:pPr>
  <w:pStyle w:val="ListParagraph"/>
  <w:spacing w:before="0" w:after="200"/>
</w:pPr>
```

```
  鄰近（壞）：

  ...上一節文本結束。
                                        <- 12pt 間隙
  ## 章節標題
                                        <- 12pt 間隙（相同！）
  新節第一段。

  標題漂浮在節之間。不清楚它屬於什麼。
```

```
  列表分組（壞）：

  考慮這些因素：
                                        <- 10pt 間隙
    - 第一項
                                        <- 10pt 間隙（與段落相同）
    - 第二項
                                        <- 10pt 間隙
    - 第三項
                                        <- 10pt 間隙
  下一段。

  列表不像一組。每項看起來像
  碰巧帶項目符號的獨立段落。
```

### 快速測試

1. **遮擋測試**：遮擋標題文本。僅看留白，你能說出標題屬於哪個文本塊嗎？若上下間隙相等，答案是"否"。
2. **數字檢查**：標題的 `w:before` 應至少是 `w:after` 的 2 倍。常見好值：before=360 / after=120，或 before=240 / after=80。
3. **列表檢查**：列表項的 `w:after` 應小於正文 `w:after` 的一半。若正文用 160，列表項應用 40-60。

## 4. 對齊與網格

### 為何有效

對齊創造眼睛沿頁面向下跟隨的隱形線。當元素共享同一邊緣，讀者感知到秩序和意圖。當元素略微錯位（差幾 twips），頁面看起來潦草，即便讀者無法有意識地識別原因。

**左對齊 vs 兩端對齊：**

- **左對齊**（右參差）最適合英文和其他拉丁文字語言。不齊的右邊實際上有助於閱讀，因為每行有獨特輪廓，使眼睛更易找到下一行。兩端對齊強制不均勻的詞間距，產生穿過段落縱向流動的 distracting "白河"。

- **兩端對齊**最適合 CJK 文本。中文、日文、韓文字符設計上等寬 — 每個佔據隱形網格中相同單元。兩端對齊完美保留此網格。CJK 文本右參差會破壞網格，看起來不整潔。

**縮進規則**：用首行縮進或段間距分隔段落 — 絕不同時用。它們服務於同一目的（標記段落邊界）。同時用既浪費空間又造成視覺結巴。

- 西方慣例：段間距（無縮進）更現代。
- CJK 慣例：2 字符首行縮進是標準。
- 學術慣例：0.5 英寸首行縮進是傳統。

### 好的示例

```xml
<!-- 英文正文：左對齊，段間距，無縮進 -->
<w:pPr>
  <w:jc w:val="left"/>
  <w:spacing w:after="160" w:line="276" w:lineRule="auto"/>
  <!-- 無 w:ind firstLine -->
</w:pPr>

<!-- CJK 正文：兩端對齊，首行縮進 2 字符，無段間距 -->
<w:pPr>
  <w:jc w:val="both"/>
  <w:spacing w:after="0" w:line="360" w:lineRule="auto"/>
  <w:ind w:firstLineChars="200"/>
</w:pPr>

<!-- 製表位創建對齊的列 -->
<w:pPr>
  <w:tabs>
    <w:tab w:val="left" w:pos="2880"/>   <!-- 2 英寸 -->
    <w:tab w:val="right" w:pos="9360"/>  <!-- 6.5 英寸（右邊距） -->
  </w:tabs>
</w:pPr>
```

```
  英文段落分隔（好 — 間距，無縮進）：

  這是第一段，帶一些文本
  自然換行到第二行。

  這是第二段。上方的間隙
  清晰標記了邊界。


  CJK 段落分隔（好 — 縮進，無間距）：

  　　第一段正文內容從這裡開始，使用兩個字符
  的首行縮進來標記段落邊界。
  　　第二段緊跟其後，沒有段間距，但首行縮進
  清晰地標識了新段落的開始。
```

### 壞的示例

```xml
<!-- 英文正文：兩端對齊（產生詞距白河） -->
<w:pPr>
  <w:jc w:val="both"/>
  <w:spacing w:after="160" w:line="276" w:lineRule="auto"/>
  <w:ind w:firstLine="720"/>  <!-- 既縮進又間距：冗餘 -->
</w:pPr>

<!-- CJK 正文：左對齊（破壞字符網格） -->
<w:pPr>
  <w:jc w:val="left"/>
  <w:spacing w:after="200" w:line="276" w:lineRule="auto"/>
  <!-- 無縮進，改用間距 — 對 CJK 不地道 -->
</w:pPr>
```

問題：
- 兩端對齊的英文文本配窄欄會產生不均勻詞距。
- 同時用首行縮進和段間距是冗餘的。
- 左對齊的 CJK 破壞了 CJK 讀者期望的字符網格。
- 用間距分隔的 CJK 看起來像翻譯的西方版式。

### 快速測試

1. **白河測試**：在兩端對齊的英文文本中，眯眼尋找穿過段落的縱向白色條紋。若看到，切換到左對齊或增加欄寬。
2. **雙重信號檢查**：文檔是否同時用首行縮進和段間距？若是，移除一個。CJK/學術選縮進，現代西方選間距。
3. **製表位對齊**：若用製表位做列，文檔中所有制表位是否用相同位置？不一致的製表位產生鋸齒狀的隱形網格線。

## 5. 重複與一致性

### 為何有效

一致性是信任信號。當讀者看到每個 H2 都相同、每個表格遵循同一模式、每個頁碼都在同一位置，他們不自覺地信任文檔是用心製作的。一處不一致 — 一個 H2 是 15pt 而非 14pt、一個表格有不同邊框 — 就破壞了這種信任，讓讀者質疑內容。

一致性還降低認知負荷。一旦讀者學到"粗體深藍 = 章節標題"，他們就不再花精力識別結構，完全專注於內容。每處不一致都迫使他們重新評估："這是一種不同的標題，還是有人忘了應用樣式？"

實現規則很簡單：**用命名樣式，而非直接格式。** 若你將 Heading2 定義為樣式並處處應用，一致性是自動的。若你逐個手動設置字號、粗體、顏色，不一致不可避免。

### 好的示例

```xml
<!-- 在 styles.xml 中一次性定義樣式 -->
<w:style w:type="paragraph" w:styleId="Heading2">
  <w:name w:val="heading 2"/>
  <w:basedOn w:val="Normal"/>
  <w:next w:val="Normal"/>
  <w:pPr>
    <w:keepNext/>
    <w:keepLines/>
    <w:spacing w:before="360" w:after="120"/>
    <w:outlineLvl w:val="1"/>
  </w:pPr>
  <w:rPr>
    <w:rFonts w:asciiTheme="majorHAnsi" w:hAnsiTheme="majorHAnsi"/>
    <w:b/>
    <w:sz w:val="32"/>
    <w:color w:val="1F3864"/>
  </w:rPr>
</w:style>

<!-- 一致應用：每個 H2 引用該樣式 -->
<w:p>
  <w:pPr>
    <w:pStyle w:val="Heading2"/>
    <!-- 無直接格式覆蓋 -->
  </w:pPr>
  <w:r><w:t>市場分析</w:t></w:r>
</w:p>
```

使用表格樣式時，一次性定義並用於每個表格：

```xml
<!-- 所有表格引用同一樣式 -->
<w:tblPr>
  <w:tblStyle w:val="GridTable4Accent1"/>
  <w:tblW w:w="0" w:type="auto"/>
</w:tblPr>
```

### 壞的示例

```xml
<!-- 第一個 H2：手動格式化 -->
<w:p>
  <w:pPr>
    <w:spacing w:before="360" w:after="120"/>
  </w:pPr>
  <w:r>
    <w:rPr>
      <w:b/>
      <w:sz w:val="32"/>
      <w:color w:val="1F3864"/>
    </w:rPr>
    <w:t>市場分析</w:t>
  </w:r>
</w:p>

<!-- 第二個 H2：略有不同（16pt 還是 16pt？不，15pt！） -->
<w:p>
  <w:pPr>
    <w:spacing w:before="240" w:after="160"/>  <!-- 間距不同！ -->
  </w:pPr>
  <w:r>
    <w:rPr>
      <w:b/>
      <w:sz w:val="30"/>   <!-- 15pt 而非 16pt！ -->
      <w:color w:val="2E74B5"/>  <!-- 藍色色調不同！ -->
    </w:rPr>
    <w:t>財務概覽</w:t>
  </w:r>
</w:p>
```

問題：
- 無樣式引用 — 一切都是直接格式。
- 第二個 H2 字號（30 vs 32）、顏色、間距都不同。
- 若有 20 個標題，每個都可能略有漂移。
- 日後改設計意味著逐個編輯每個標題。

### 快速測試

1. **樣式審計**：每個段落是否引用 `w:pStyle`？若發現只有直接格式無樣式的段落，那是一致性風險。
2. **搜索差異**：在 XML 中搜索與 `w:b`（粗體）一起使用的所有 `w:sz` 值。若本應同級的標題找到三個不同字號，存在不一致。
3. **表格檢查**：文檔中所有表格是否引用同一 `w:tblStyle`？若某些表格手動定義邊框而其他用樣式，文檔會顯得斑駁。
4. **頁碼**：檢查頁眉/頁腳內容是否定義在默認節屬性中並被所有節繼承，而非每節不一致地重新定義。

## 6. 視覺層級與流向

### 為何有效

設計良好的文檔引導讀者眼睛沿可預測路徑：頂部標題、下方副標題、作為路標的章節標題、作為主要內容的正文、作為支撐細節的腳註和題注。此流向映射閱讀優先級 — 最重要的信息視覺上最突出。

層級中每級必須**與相鄰級可區分**。H1 不同於正文還不夠；H1 還必須明顯不同於 H2，H2 不同於 H3。若任何兩個相鄰級太相似，層級在該點崩塌。

有效層級使用**多個同時信號**：

| 級別    | 字號  | 字重  | 顏色   | 上方間距 |
|----------|-------|---------|---------|---------------|
| 標題    | 26pt  | 粗體    | #1F3864 | 0（頂部）       |
| 副標題 | 15pt  | 常規 | #4472C4 | 4pt           |
| H1       | 20pt  | 粗體    | #1F3864 | 24pt          |
| H2       | 16pt  | 粗體    | #1F3864 | 18pt          |
| H3       | 13pt  | 粗體    | #1F3864 | 12pt          |
| 正文     | 11pt  | 常規 | #333333 | 0pt           |
| 題注  | 9pt   | 斜體  | #666666 | 4pt           |
| 腳註 | 9pt   | 常規 | #666666 | 0pt           |

注意每級至少在兩個維度上區別於相鄰級（字號+字重，或字號+顏色，或字重+樣式）。單維度差異脆弱，易被忽略。

**分節符**在長文檔中創造節奏。每個主要章節（H1）前的分頁給讀者心理重置。章節內，一致的標題+正文模式創造可預測的節拍，使長文檔不那麼令人生畏。

### 好的示例

```xml
<!-- 標題：大、粗體、海軍藍、居中 -->
<w:style w:type="paragraph" w:styleId="Title">
  <w:pPr>
    <w:jc w:val="center"/>
    <w:spacing w:after="80"/>
  </w:pPr>
  <w:rPr>
    <w:b/>
    <w:sz w:val="52"/>
    <w:color w:val="1F3864"/>
  </w:rPr>
</w:style>

<!-- 副標題：中、常規字重、較淺藍、居中 -->
<w:style w:type="paragraph" w:styleId="Subtitle">
  <w:pPr>
    <w:jc w:val="center"/>
    <w:spacing w:after="320"/>
  </w:pPr>
  <w:rPr>
    <w:sz w:val="30"/>
    <w:color w:val="4472C4"/>
  </w:rPr>
</w:style>

<!-- H1：段前分頁，大粗體海軍藍 -->
<w:style w:type="paragraph" w:styleId="Heading1">
  <w:pPr>
    <w:pageBreakBefore/>
    <w:keepNext/>
    <w:keepLines/>
    <w:spacing w:before="480" w:after="160"/>
    <w:outlineLvl w:val="0"/>
  </w:pPr>
  <w:rPr>
    <w:b/>
    <w:sz w:val="40"/>
    <w:color w:val="1F3864"/>
  </w:rPr>
</w:style>

<!-- 題注：小、斜體、灰 -->
<w:style w:type="paragraph" w:styleId="Caption">
  <w:pPr>
    <w:spacing w:before="80" w:after="200"/>
  </w:pPr>
  <w:rPr>
    <w:i/>
    <w:sz w:val="18"/>
    <w:color w:val="666666"/>
  </w:rPr>
</w:style>
```

```
  視覺流向（好）：

  +----------------------------------+
  |                                  |
  |     2025 年度報告                |  <- 標題：26pt 粗體海軍藍居中
  |     Acme 公司                    |  <- 副標題：15pt 常規藍
  |                                  |
  |                                  |
  +----------------------------------+

  +----------------------------------+
  |                                  |
  |  1. 執行摘要                     |  <- H1：20pt 粗體海軍藍（分頁）
  |                                  |
  |  介紹年度主要發現的               |  <- 正文：11pt 常規灰
  |  正文。                          |
  |                                  |
  |  1.1 營收亮點                    |  <- H2：16pt 粗體海軍藍
  |                                  |
  |  營收同比增長 23%，               |  <- 正文
  |  受...驅動。                     |
  |                                  |
  |  圖 1：營收增長                  |  <- 題注：9pt 斜體灰
  |                                  |
  +----------------------------------+

  每級立即可辨。眼睛自然流向
  標題 -> 標題 -> 正文 -> 題注。
```

### 壞的示例

```xml
<!-- 所有標題與正文同色，字號差異極小 -->
<w:style w:type="paragraph" w:styleId="Heading1">
  <w:rPr>
    <w:b/>
    <w:sz w:val="28"/>       <!-- 14pt — 僅比正文高 3pt -->
    <w:color w:val="000000"/> <!-- 與正文同色 -->
  </w:rPr>
</w:style>

<!-- 題注與正文同號，非斜體 -->
<w:style w:type="paragraph" w:styleId="Caption">
  <w:rPr>
    <w:sz w:val="22"/>        <!-- 與正文同 11pt！ -->
    <w:color w:val="000000"/> <!-- 與正文同色 -->
  </w:rPr>
</w:style>

<!-- 主要章節間無分頁 -->
<!-- H1 無 pageBreakBefore、keepNext 或 keepLines -->
```

問題：
- H1 14pt 與正文 11pt 太近（比率 1.27 — 孤立看可接受，但配黑色匹配正文，層級很弱）。
- 題注與正文無法區分。
- 無分頁意味著主要章節相互滲透，無視覺節奏。
- 一切都是黑色，顏色提供零層級信號。

### 快速測試

1. **眯眼測試**：看整頁時模糊視線。你應看到 3-4 個不同"灰度級"。若頁面看起來是統一色調，層級太扁。
2. **掃描測試**：快速翻頁。每頁能否在一秒內識別章節邊界？若是，視覺層級有效。若頁面模糊成片，H1 需更強區分。
3. **相鄰級測試**：對每個標題級，檢查它是否在以下至少 2 項上區別於下一級：字號、字重、顏色、樣式（斜體）。單維度差異會丟失。
4. **節奏測試**：超過 10 頁的文檔中，主要章節（H1）是否從新頁開始？若否，長文檔會感覺是無差異的流。給 Heading1 加 `w:pageBreakBefore`。

## 總結：決策清單

拿不準排版選擇時，過一遍這些檢查：

| 原則 | 問題 | 若否... |
|-----------|----------|----------|
| 留白 | 頁面是否至少有 30% 留白？ | 增加頁邊距或間距 |
| 對比 | 眯眼能否數出標題級數？ | 增大字號比率（目標 1.25x） |
| 鄰近 | 每個標題是否明確屬於下方文本？ | 使段前 > 段後（2:1） |
| 對齊 | 英文是否左對齊、CJK 是否兩端對齊？ | 切換對齊模式 |
| 重複 | 所有同級元素是否用同一樣式？ | 用樣式替換直接格式 |
| 層級 | 一臂距離能否看到文檔結構？ | 增加更多區分信號 |

**當兩個原則衝突時，按此順序優先：**

1. **可讀性**（留白、行距）— 始終優先
2. **層級**（對比、比例）— 讀者必須找到所需
3. **一致性**（重複）— 建立信任
4. **美學**（對齊、分組）— 收尾點綴
