# 文檔設計好壞對比 — 具體 OpenXML 示例

一份並排參考，展示常見設計錯誤及其修復，含精確 OpenXML 參數值。用於培養對"什麼讓文檔看起來專業而非業餘"的直覺。

格式：每個對比先展示**壞**版本（錯誤），再展示**好**版本（修復），附 OpenXML 標記和簡短說明。

---

## 1. 字號災難

### 1a. 無層級 — 一切同號

**壞：正文=12pt，H1=12pt 粗體**
```
┌──────────────────────────────────┐
│ 引言                             │  ← 12pt 粗體… 同樣視覺重量
│ 這是報告的正文。                  │  ← 12pt 常規
│ 討論季度評審的發現。              │
│ 方法論                            │  ← 章節從哪開始？
│ 我們從企業的三個來源              │
│ 收集了數據。                      │
└──────────────────────────────────┘
```
```xml
<!-- H1：粗體但與正文同號 — 無視覺分隔 -->
<w:rPr><w:b/><w:sz w:val="24"/></w:rPr>
<!-- 正文 -->
<w:rPr><w:sz w:val="24"/></w:rPr>
```

**好：模數比例 — 正文=11pt，H3=13pt，H2=16pt，H1=20pt**
```
┌──────────────────────────────────┐
│                                  │
│ 引言                             │  ← 20pt，明顯是標題
│                                  │
│ 這是報告的正文。                  │  ← 11pt，舒適閱讀字號
│ 討論季度評審的發現。              │
│                                  │
│ 方法論                            │  ← 20pt，章節分隔明顯
│                                  │
│ 我們從企業的三個來源              │
│ 收集了數據。                      │
└──────────────────────────────────┘
```
```xml
<!-- H1：20pt = w:sz 40 -->
<w:rPr><w:rFonts w:ascii="Calibri Light"/><w:sz w:val="40"/></w:rPr>
<!-- H2：16pt = w:sz 32 -->
<w:rPr><w:rFonts w:ascii="Calibri Light"/><w:sz w:val="32"/></w:rPr>
<!-- H3：13pt = w:sz 26，粗體 -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:b/><w:sz w:val="26"/></w:rPr>
<!-- 正文：11pt = w:sz 22 -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:sz w:val="22"/></w:rPr>
```
**為何更好：** 清晰的字號遞進（每級約 1.25x）讓讀者無需讀一個字即可瞬間識別結構。

---

### 1b. 對比過度 — 兒童讀物感

**壞：H1=28pt 配正文=10pt（比率 2.8x）**
```
┌──────────────────────────────────┐
│                                  │
│ 季度報告                          │  ← 28pt，主導整頁
│                                  │
│ 這是設得很小的正文                │  ← 10pt，費力閱讀
│ 與標題的對比使它                  │
│ 感覺像海報。                      │
└──────────────────────────────────┘
```
```xml
<w:rPr><w:b/><w:sz w:val="56"/></w:rPr>  <!-- 28pt 標題 -->
<w:rPr><w:sz w:val="20"/></w:rPr>         <!-- 10pt 正文 -->
```

**好：H1=20pt 配正文=11pt（比率約 1.8x）**
```xml
<w:rPr><w:sz w:val="40"/></w:rPr>  <!-- 20pt 標題 -->
<w:rPr><w:sz w:val="22"/></w:rPr>  <!-- 11pt 正文 -->
```
**為何更好：** 標題與正文比率在 1.5x 到 2.0x 之間讀起來像"有結構"而非"在喊叫"。

## 2. 間距罪行

### 2a. 文字牆 — 無段距或行距

**壞：單倍行距，段間 0pt**
```
┌──────────────────────────────────┐
│發現表明培訓時長與績效             │
│指標之間存在強相關性。             │
│進一步分析顯示，預算               │  ← 無間隙 — 新段落從哪
│更高的部門在所有衡量類別           │     開始？
│中都取得了更好結果。               │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:spacing w:line="240" w:lineRule="auto"/>  <!-- 1.0 間距 (240/240) -->
  <w:spacing w:after="0"/>                     <!-- 無段距 -->
</w:pPr>
```

**好：1.15x 行距，每段後 8pt**
```
┌──────────────────────────────────┐
│發現表明培訓時長與績效             │
│指標之間存在強相關性。             │  ← 行間略多空氣
│                                  │  ← 8pt 間隙標記新段落
│進一步分析顯示，預算               │
│更高的部門在所有衡量類別           │
│中都取得了更好結果。               │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:spacing w:line="276" w:lineRule="auto"/>  <!-- 1.15x (276/240) -->
  <w:spacing w:after="160"/>                   <!-- 8pt = 160 twips -->
</w:pPr>
```
**為何更好：** 行距給每行呼吸空間；段距分隔意思而不浪費整空行。

---

### 2b. 漂浮標題 — 上下間距相同

**壞：標題前 12pt 後 12pt**
```
┌──────────────────────────────────┐
│ ...上一節結束。                  │
│                                  │  ← 12pt 間隙
│ 第二節                           │  ← 標題漂浮在中間
│                                  │  ← 12pt 間隙
│ 第二節內容開始。                  │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:spacing w:before="240" w:after="240"/>  <!-- 兩邊 12pt -->
</w:pPr>
```

**好：標題前 24pt 後 8pt**
```
┌──────────────────────────────────┐
│ ...上一節結束。                  │
│                                  │
│                                  │  ← 24pt 間隙 — 清晰分節
│ 第二節                           │  ← 標題靠近其內容
│                                  │  ← 8pt 間隙
│ 第二節內容開始。                  │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:spacing w:before="480" w:after="160"/>  <!-- 前 24pt，後 8pt -->
</w:pPr>
```
**為何更好：** 鄰近原則：標題屬於其後的文本，所以上方多空間、下方少空間將其錨定到內容。

---

### 2c. 浪費間隙 — 到處巨大間距

**壞：每段後 24pt，包括正文**
```
┌──────────────────────────────────┐
│ 第一段文本在此。                  │
│                                  │
│                                  │  ← 每段後 24pt 間隙
│                                  │
│ 第二段文本在此。                  │
│                                  │
│                                  │
│                                  │
│ 第三段。                          │  ← 文檔看起來大多是留白
└──────────────────────────────────┘
```
```xml
<w:spacing w:after="480"/>  <!-- 每段後 24pt = 480 twips -->
```

**好：成比例間距 — 正文=8pt，H2 後=6pt，H1 後=10pt**
```xml
<!-- 正文段落 -->
<w:spacing w:after="160"/>   <!-- 正文後 8pt -->
<!-- H1 -->
<w:spacing w:before="480" w:after="200"/>  <!-- 前 24pt，後 10pt -->
<!-- H2 -->
<w:spacing w:before="320" w:after="120"/>  <!-- 前 16pt，後 6pt -->
```
**為何更好：** 間距應按元素角色變化，創造視覺節奏而非統一間隙。

## 3. 頁邊距錯誤

### 3a. 擁擠頁邊距 — 文本貼到邊緣

**壞：四邊 0.5in**
```
┌────────────────────────────────────────────────┐
│文本幾乎從紙邊開始，一路橫跨，形成極長的行，    │
│難以從行尾追蹤回行首。眼睛每次換行都丟失位置。 │
└────────────────────────────────────────────────┘
```
```xml
<w:pgMar w:top="720" w:right="720" w:bottom="720" w:left="720"/>
<!-- 720 twips = 0.5in — Letter 紙上行長約 7.5in -->
```

**好：1in 頁邊距（標準）**
```xml
<w:pgMar w:top="1440" w:right="1440" w:bottom="1440" w:left="1440"/>
<!-- 1440 twips = 1.0in — 行長約 6.5in，對 11pt 正文理想 -->
```
**為何更好：** 最佳行長 60-75 字符。11pt Calibri 下，6.5in 寬度約每行 70 字符。

---

### 3b. 過度填充頁邊距 — 看起來像內容在躲藏

**壞：短文檔用 2in 頁邊距**
```xml
<w:pgMar w:top="2880" w:right="2880" w:bottom="2880" w:left="2880"/>
<!-- 2880 twips = 2.0in — 僅 4.5in 文本寬，看起來填充過度 -->
```

**好：1in 標準，或正式文檔用 1.25in**
```xml
<!-- 標準 -->
<w:pgMar w:top="1440" w:right="1440" w:bottom="1440" w:left="1440"/>
<!-- 正式/裝訂文檔帶裝訂線 -->
<w:pgMar w:top="1440" w:right="1440" w:bottom="1440" w:left="1800" w:gutter="0"/>
<!-- 1800 twips = 1.25in 左側裝訂線 -->
```
**為何更好：** 頁邊距應為內容取景，而非壓倒內容。1-1.25in 適用於幾乎所有商業和學術文檔。

## 4. 表格醜陋

### 4a. 監獄網格 — 每個單元格全邊框

**壞：每個單元格四邊 1pt 邊框**
```
┌───────┬───────┬───────┬───────┐
│ 姓名  │ 部門  │ 分數  │ 等級  │
├───────┼───────┼───────┼───────┤
│ 張三  │ 工程  │ 92    │ A     │
├───────┼───────┼───────┼───────┤
│ 李四  │ 銷售  │ 85    │ B     │
├───────┼───────┼───────┼───────┤
│ 王五  │ 工程  │ 78    │ C+    │
└───────┴───────┴───────┴───────┘
```
```xml
<w:tcBorders>
  <w:top w:val="single" w:sz="4" w:color="000000"/>
  <w:left w:val="single" w:sz="4" w:color="000000"/>
  <w:bottom w:val="single" w:sz="4" w:color="000000"/>
  <w:right w:val="single" w:sz="4" w:color="000000"/>
</w:tcBorders>
```

**好：三線表 — 頂粗、表頭下中、表底粗**
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 1.5pt 頂邊框
  姓名    部門    分數    等級
──────────────────────────────────  ← 0.75pt 表頭分隔
  張三    工程    92      A
  李四    銷售    85      B
  王五    工程    78      C+
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 1.5pt 底邊框
```
```xml
<!-- 表頭行單元格頂邊框 -->
<w:top w:val="single" w:sz="12" w:color="000000"/>    <!-- 1.5pt -->
<w:left w:val="nil"/><w:right w:val="nil"/>
<w:bottom w:val="single" w:sz="6" w:color="000000"/>  <!-- 0.75pt -->

<!-- 數據行單元格：無左/右/頂邊框 -->
<w:top w:val="nil"/><w:left w:val="nil"/><w:right w:val="nil"/>
<w:bottom w:val="nil"/>

<!-- 末行底邊框 -->
<w:bottom w:val="single" w:sz="12" w:color="000000"/> <!-- 1.5pt -->
```
**為何更好：** 移除內部邊框讓眼睛自由掃描數據。三條線提供結構而無視覺雜亂。

---

### 4b. 文本貼邊框 — 無單元格內邊距

**壞：零單元格邊距**
```
┌──────────┬──────────┐
│姓名      │部門      │  ← 文本緊貼邊框
├──────────┼──────────┤
│張三      │工程部    │
└──────────┴──────────┘
```
```xml
<w:tcMar>
  <w:top w:w="0" w:type="dxa"/>
  <w:start w:w="0" w:type="dxa"/>
  <w:bottom w:w="0" w:type="dxa"/>
  <w:end w:w="0" w:type="dxa"/>
</w:tcMar>
```

**好：垂直 0.08in，水平 0.12in 內邊距**
```xml
<w:tcMar>
  <w:top w:w="115" w:type="dxa"/>      <!-- ~0.08in = 115 twips -->
  <w:start w:w="173" w:type="dxa"/>    <!-- ~0.12in = 173 twips -->
  <w:bottom w:w="115" w:type="dxa"/>
  <w:end w:w="173" w:type="dxa"/>
</w:tcMar>
```
**為何更好：** 內邊距給單元格內文本呼吸空間，使每個值更易讀。

---

### 4c. 隱形表頭 — 表頭行與數據同樣式

**壞：表頭行與數據無法區分**
```xml
<!-- 表頭單元格 run 屬性 — 與數據相同 -->
<w:rPr><w:sz w:val="22"/></w:rPr>
```

**好：粗體表頭文本、微妙背景填充、底邊框**
```xml
<!-- 表頭單元格 run 屬性 -->
<w:rPr><w:b/><w:sz w:val="22"/><w:color w:val="333333"/></w:rPr>

<!-- 表頭單元格底紋 -->
<w:tcPr>
  <w:shd w:val="clear" w:color="auto" w:fill="F2F2F2"/>  <!-- 淺灰背景 -->
  <w:tcBorders>
    <w:bottom w:val="single" w:sz="8" w:color="666666"/>  <!-- 1pt 分隔 -->
  </w:tcBorders>
</w:tcPr>

<!-- 標記行為表頭（分頁時重複） -->
<w:trPr><w:tblHeader/></w:trPr>
```
**為何更好：** 鮮明的表頭樣式讓讀者瞬間定位列含義，尤其在跨頁長表中。`w:tblHeader` 元素確保表頭行在每頁重複。

## 5. 字體配對失敗

### 5a. 視覺混亂 — 字體過多

**壞：一份文檔 4+ 種字體**
```xml
<!-- H1 用 Impact -->
<w:rPr><w:rFonts w:ascii="Impact"/><w:sz w:val="40"/></w:rPr>
<!-- H2 用 Georgia -->
<w:rPr><w:rFonts w:ascii="Georgia"/><w:sz w:val="32"/></w:rPr>
<!-- 正文用 Verdana -->
<w:rPr><w:rFonts w:ascii="Verdana"/><w:sz w:val="22"/></w:rPr>
<!-- 題注用 Courier New -->
<w:rPr><w:rFonts w:ascii="Courier New"/><w:sz w:val="18"/></w:rPr>
```

**好：一個字族配字重變化，或兩個互補字族**
```xml
<!-- H1：Calibri Light（Calibri 字族的細字重） -->
<w:rPr><w:rFonts w:ascii="Calibri Light"/><w:sz w:val="40"/></w:rPr>
<!-- H2：Calibri Light -->
<w:rPr><w:rFonts w:ascii="Calibri Light"/><w:sz w:val="32"/></w:rPr>
<!-- 正文：Calibri（常規字重） -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:sz w:val="22"/></w:rPr>
<!-- 題注：Calibri -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:sz w:val="18"/></w:rPr>
```
**為何更好：** 限制為一或兩個字族創造視覺連貫。用字號和字重變化，而非字體變化。

---

### 5b. 性格不匹配 — Comic Sans 遇上 Times New Roman

**壞：**
```xml
<w:rPr><w:rFonts w:ascii="Comic Sans MS"/><w:sz w:val="36"/></w:rPr>  <!-- 標題 -->
<w:rPr><w:rFonts w:ascii="Times New Roman"/><w:sz w:val="24"/></w:rPr> <!-- 正文 -->
```

**好：性格兼容的字體**
```xml
<w:rPr><w:rFonts w:ascii="Calibri Light"/><w:sz w:val="36"/></w:rPr>   <!-- 標題 -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:sz w:val="22"/></w:rPr>          <!-- 正文 -->
```
**為何更好：** 配對的字體應共享相似的正式程度和幾何性格。Comic Sans 俏皮/非正式；Times New Roman 正式/傳統。它們衝突。

---

### 5c. 一切粗體 — 什麼都不突出

**壞：正文、標題、題注、一切都粗體**
```xml
<w:rPr><w:b/><w:sz w:val="40"/></w:rPr>  <!-- 標題：粗體 -->
<w:rPr><w:b/><w:sz w:val="22"/></w:rPr>  <!-- 正文：也粗體 -->
<w:rPr><w:b/><w:sz w:val="18"/></w:rPr>  <!-- 題注：仍粗體 -->
```

**好：粗體僅用於標題和關鍵術語**
```xml
<w:rPr><w:b/><w:sz w:val="40"/></w:rPr>   <!-- H1：粗體 -->
<w:rPr><w:sz w:val="32"/></w:rPr>          <!-- H2：僅字號即可 -->
<w:rPr><w:sz w:val="22"/></w:rPr>          <!-- 正文：常規字重 -->
<w:rPr><w:b/><w:sz w:val="22"/></w:rPr>    <!-- 內聯關鍵術語：粗體 -->
<w:rPr><w:sz w:val="18"/></w:rPr>          <!-- 題注：常規，小 -->
```
**為何更好：** 一切都強調時，什麼都沒強調。粗體應是信號，而非默認。

---

## 6. 顏色濫用

### 6a. 彩虹標題

**壞：每個標題級一種不同亮色**
```xml
<w:rPr><w:color w:val="FF0000"/><w:sz w:val="40"/></w:rPr>  <!-- H1：紅 -->
<w:rPr><w:color w:val="00AA00"/><w:sz w:val="32"/></w:rPr>  <!-- H2：綠 -->
<w:rPr><w:color w:val="0000FF"/><w:sz w:val="26"/></w:rPr>  <!-- H3：藍 -->
```

**好：標題單一強調色，正文黑或深灰**
```xml
<!-- 所有標題用同一柔和強調色 -->
<w:rPr><w:color w:val="1F4E79"/><w:sz w:val="40"/></w:rPr>  <!-- H1：深藍 -->
<w:rPr><w:color w:val="1F4E79"/><w:sz w:val="32"/></w:rPr>  <!-- H2：同藍 -->
<w:rPr><w:color w:val="1F4E79"/><w:sz w:val="26"/></w:rPr>  <!-- H3：同藍 -->
<!-- 正文近黑 -->
<w:rPr><w:color w:val="333333"/><w:sz w:val="22"/></w:rPr>
```
**為何更好：** 單一強調色建立品牌一致性。多種亮色爭奪注意力，顯得不專業。

---

### 6b. 低對比 — 白底淺灰

**壞：白底 #CCCCCC 文本**
```xml
<w:rPr><w:color w:val="CCCCCC"/></w:rPr>
<!-- 對比度：約 1.6:1 — 不達 WCAG AA（最低 4.5:1） -->
```

**好：白底 #333333 文本**
```xml
<w:rPr><w:color w:val="333333"/></w:rPr>
<!-- 對比度：約 12:1 — 達 WCAG AAA -->
```
**為何更好：** 足夠對比不僅是無障礙要求；它使文本對每個人都更易讀，尤其在打印文檔中。

---

### 6c. 亮色正文

**壞：飽和色正文**
```xml
<w:rPr><w:color w:val="0066FF"/><w:sz w:val="22"/></w:rPr>  <!-- 藍色正文 -->
```

**好：顏色僅用於標題和內聯強調**
```xml
<!-- 正文：中性深色 -->
<w:rPr><w:color w:val="333333"/><w:sz w:val="22"/></w:rPr>
<!-- 超鏈接：此處顏色是功能性 -->
<w:rPr><w:color w:val="0563C1"/><w:u w:val="single"/></w:rPr>
```
**為何更好：** 彩色正文在長閱讀中導致眼疲勞。顏色留給需吸引注意的元素（標題、鏈接、警告）。

---

## 7. 列表格式問題

### 7a. 項目符號貼頁邊距 — 無縮進

**壞：列表項從左邊距開始**
```
┌──────────────────────────────────┐
│這是一段文本。                    │
│• 第一項                          │  ← 符號在頁邊距，無縮進
│• 第二項                          │
│• 第三項                          │
│下一段在此繼續。                  │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:ind w:left="0" w:hanging="0"/>
</w:pPr>
```

**好：0.25in 左縮進，項目符號懸掛縮進**
```
┌──────────────────────────────────┐
│這是一段文本。                    │
│   • 第一項                       │  ← 縮進，明顯是列表
│   • 第二項                       │
│   • 第三項                       │
│下一段在此繼續。                  │
└──────────────────────────────────┘
```
```xml
<w:pPr>
  <w:ind w:left="360" w:hanging="360"/>  <!-- 0.25in = 360 twips -->
  <w:numPr>
    <w:ilvl w:val="0"/>
    <w:numId w:val="1"/>
  </w:numPr>
</w:pPr>
```
嵌套列表每級遞增 360 twips：
```xml
<!-- 第 1 級 -->
<w:ind w:left="720" w:hanging="360"/>   <!-- 左 0.5in -->
<!-- 第 2 級 -->
<w:ind w:left="1080" w:hanging="360"/>  <!-- 左 0.75in -->
```
**為何更好：** 縮進視覺上將列表與正文分開，使嵌套級別清晰。

---

### 7b. 列表項用完整段距

**壞：列表項與正文一樣 8-10pt 間距**
```
┌──────────────────────────────────┐
│   • 第一項                       │
│                                  │  ← 10pt 間隙 — 看起來像獨立
│   • 第二項                       │     段落，而非列表
│                                  │
│   • 第三項                       │
└──────────────────────────────────┘
```
```xml
<w:spacing w:after="200"/>  <!-- 每個列表項後 10pt -->
```

**好：列表項間緊密間距（2-4pt）**
```
┌──────────────────────────────────┐
│   • 第一項                       │
│   • 第二項                       │  ← 2pt 間隙 — 內聚列表
│   • 第三項                       │
└──────────────────────────────────┘
```
```xml
<w:spacing w:after="40" w:line="276" w:lineRule="auto"/>  <!-- 後 2pt -->
<!-- 或 4pt： -->
<w:spacing w:after="80"/>
```
**為何更好：** 緊密間距將列表項歸為單一單元，符合讀者對列表行為的期望。

## 8. 頁眉/頁腳問題

### 8a. 頁眉文本過大 — 與正文爭搶

**壞：頁眉 12pt，與正文同**
```
┌──────────────────────────────────┐
│ 季度報告 - 2025 第三季度         │  ← 12pt 頁眉，與正文同
│──────────────────────────────────│
│ 引言                             │
│ 這是正文…                        │  ← 12pt 正文 — 頁眉分散注意
└──────────────────────────────────┘
```
```xml
<!-- 頁眉段落 -->
<w:rPr><w:sz w:val="24"/></w:rPr>  <!-- 12pt，與正文同 -->
```

**好：頁眉 9pt，灰色，微妙**
```
┌──────────────────────────────────┐
│ 季度報告 - 2025 第三季度         │  ← 9pt，灰 — 在場但安靜
│──────────────────────────────────│
│ 引言                             │
│ 這是正文…                        │  ← 正文作為主體突出
└──────────────────────────────────┘
```
```xml
<!-- 頁眉段落 -->
<w:rPr>
  <w:sz w:val="18"/>                <!-- 9pt -->
  <w:color w:val="808080"/>         <!-- 中灰 -->
</w:rPr>
<w:pPr>
  <w:pBdr>
    <w:bottom w:val="single" w:sz="4" w:color="D9D9D9"/>  <!-- 微妙分隔 -->
  </w:pBdr>
</w:pPr>
```
**為何更好：** 頁眉是參考信息，非主要內容。應可讀但視覺上從屬。

## 9. CJK 特有錯誤

### 9a. 用斜體做中文強調

**壞：斜體應用於中文文本**
```xml
<w:rPr>
  <w:i/>
  <w:rFonts w:eastAsia="SimSun"/>
  <w:sz w:val="24"/>
</w:rPr>
```
CJK 字形無真正斜體形式。渲染器施加合成傾斜，看起來破損醜陋 — 字符顯得彆扭地傾斜。

**好：用粗體或著重號做中文強調**
```xml
<!-- 選項 A：粗體強調 -->
<w:rPr>
  <w:b/>
  <w:rFonts w:eastAsia="SimHei"/>  <!-- 切換到支持粗體的字體 -->
  <w:sz w:val="24"/>
</w:rPr>

<!-- 選項 B：著重號（字符下方圓點） -->
<w:rPr>
  <w:em w:val="dot"/>
  <w:rFonts w:eastAsia="SimSun"/>
  <w:sz w:val="24"/>
</w:rPr>
```
**為何更好：** 中文排版有自己的強調傳統。粗體和著重號是原生 CJK 慣例；斜體是拉丁文字概念，無法移植。

---

### 9b. 中文字符用拉丁字體

**壞：僅設 ASCII 字體，無 EastAsia 字體**
```xml
<w:rPr>
  <w:rFonts w:ascii="Arial"/>  <!-- 無 eastAsia 屬性 -->
  <w:sz w:val="24"/>
</w:rPr>
<!-- Word 回退到隨機字體。中文字符可能以錯誤度量、
     不一致筆畫寬度或缺失字形渲染。 -->
```

**好：ASCII 字體旁顯式 EastAsia 字體**
```xml
<w:rPr>
  <w:rFonts w:ascii="Calibri" w:hAnsi="Calibri" w:eastAsia="Microsoft YaHei"/>
  <w:sz w:val="22"/>
</w:rPr>
```
正式/學術中文文檔：
```xml
<w:rPr>
  <w:rFonts w:ascii="Times New Roman" w:hAnsi="Times New Roman"
            w:eastAsia="SimSun"/>
  <w:sz w:val="24"/>  <!-- 小四 12pt -->
</w:rPr>
```
**為何更好：** 設置 `w:eastAsia` 確保中文字符用為 CJK 字形設計的字體渲染，筆畫寬度、間距、度量正確。

---

### 9c. 密集 CJK 文本用英文行距

**壞：中文正文用 1.15x 行距**
```xml
<w:spacing w:line="276" w:lineRule="auto"/>  <!-- 1.15x — 對 CJK 太緊 -->
```
CJK 字符比拉丁字母更高更密。1.15x 下，中文文本行感覺擁擠難讀。

**好：CJK 正文 12pt（小四）用 1.5x 行距或固定 28pt**
```xml
<!-- 選項 A：1.5x 比例 -->
<w:spacing w:line="360" w:lineRule="auto"/>  <!-- 360/240 = 1.5x -->

<!-- 選項 B：固定 28pt（小四/12pt CJK 正文標準） -->
<w:spacing w:line="560" w:lineRule="exact"/>  <!-- 28pt = 560 twips -->
```
公文（政府文檔）三號/16pt 正文：
```xml
<w:spacing w:line="580" w:lineRule="exact"/>  <!-- 固定 29pt 行距 -->
```
**為何更好：** CJK 字符佔據完整 em 方格，無升部/降部提供自然間隙。額外行距補償，改善密集文本塊的可讀性。

## 10. 整體文檔質感

### 學生作業 vs 專業文檔

**壞："學生作業" — 每個設置都是 Word 默認，無有意選擇**
```xml
<!-- 一切默認：Calibri 11pt，無標題樣式，1.08 間距 -->
<w:rPr><w:rFonts w:ascii="Calibri"/><w:sz w:val="22"/></w:rPr>
<w:pPr><w:spacing w:after="160" w:line="259" w:lineRule="auto"/></w:pPr>
<!-- 標題：僅粗體正文，無樣式應用 -->
<w:rPr><w:b/><w:sz w:val="22"/></w:rPr>
<!-- 無分節符，無頁眉/頁腳，無頁碼 -->
<!-- 表格用默認全網格邊框 -->
<!-- 無有意的顏色或間距變化 -->
```

**好：每個層級的刻意設計**
```xml
<!-- 定義主題字體 -->
<w:rFonts w:asciiTheme="minorHAnsi" w:hAnsiTheme="minorHAnsi"/>

<!-- H1：Calibri Light 20pt，深藍，慷慨間距 -->
<w:pPr>
  <w:pStyle w:val="Heading1"/>
  <w:spacing w:before="480" w:after="200"/>
</w:pPr>
<w:rPr>
  <w:rFonts w:ascii="Calibri Light"/>
  <w:color w:val="1F4E79"/>
  <w:sz w:val="40"/>
</w:rPr>

<!-- H2：Calibri Light 16pt，同藍 -->
<w:pPr>
  <w:pStyle w:val="Heading2"/>
  <w:spacing w:before="320" w:after="120"/>
</w:pPr>
<w:rPr>
  <w:rFonts w:ascii="Calibri Light"/>
  <w:color w:val="1F4E79"/>
  <w:sz w:val="32"/>
</w:rPr>

<!-- 正文：Calibri 11pt，深灰，1.15 間距，後 8pt -->
<w:pPr>
  <w:spacing w:after="160" w:line="276" w:lineRule="auto"/>
</w:pPr>
<w:rPr>
  <w:rFonts w:ascii="Calibri"/>
  <w:color w:val="333333"/>
  <w:sz w:val="22"/>
</w:rPr>

<!-- 表格：三線樣式，帶內邊距單元格，重複表頭 -->
<!-- 頁眉/頁腳：9pt 灰帶頁碼 -->
<!-- 頁邊距：四邊 1in -->
<w:pgMar w:top="1440" w:right="1440" w:bottom="1440" w:left="1440"/>
```
**為何更好：** 專業文檔源於跨所有設計維度的刻意、一致選擇。每個元素強化同一視覺語言。讀者可能不會自覺地注意到好排版，但能感受到可信度和可讀性的差異。
