# 编程类出题细则

适用：任何编程语言、框架、架构的学习检测。出卷前先按知识点判断考什么能力，再选题型。

## 能力 → 题型

### 控制流追踪（学 if / for / while / 递归）

给一段代码，让用户写出输出或描述执行过程。

- 代码 5–15 行：太短没有追踪价值，太长变阅读耐力测试
- 必须有陷阱：边界值、短路求值、变量遮蔽——没有陷阱的追踪题是打字练习
- 递归题让用户写前 3 层展开而不是全部（防手算爆炸）

### 代码阅读（学函数 / 参数 / 返回值）

给一个函数签名+实现，判断特定输入的输出。

- 输入选边界值：空、单元素、负数、重复元素
- 评分看点：用户是否注意到参数默认值、类型转换、异常路径

### Bug 排查（学语法细节 / 常见错误）

给一段含 bug 的代码，让用户找出并修复。

- bug 必须真实常见：off-by-one、`=` vs `==`、闭包变量捕获、异步时序
- 每段代码只埋 1 个 bug；多个 bug 的题评分粒度没法做
- 修复要对，光指出位置给一半分

### 代码补全 / 改写（学 API / 语法运用）

给需求 + 骨架代码，让用户补全或用指定方式改写。

- 需求必须无歧义：输入输出说清楚，别让用户猜
- 改写题指定目标（"用 map 重写这个 for 循环"）而不是开放式重构

### 设计分析（学架构 / 设计模式 / Agent 机制）

给一个场景，让用户分析设计权衡或补全架构决策。

- 考"为什么这样设计/什么场景该换方案"，不考"XX 模式的定义是什么"
- 场景要具体到有约束条件，开放到没有唯一解的题必须有评分要点清单

## 坑

- 代码题必配"为什么"：输出对了说不清理由不算懂
- 不出"下面哪个是 XX 的定义"式背诵题——编程概念用代码考
- 代码块标注语言（```python），保证渲染高亮
- 引用的 API/语法先确认用户笔记里真的学过，不考没学过的库函数
